战略定位 · 我们在做的不是工具，是「自动化工厂」

why we exist
将一线作业人员的重复性、规则性、跨系统作业，
以 Skill 为单元沉淀，由 AI 驱动稳定执行，
形成可建设、可治理、可观测的企业生产自动化能力。
业
业务价值
把"老员工的经验"沉淀为 Skill，由 AI 7×24 稳定执行；将作业时长从分钟级压缩到秒级，错误率单向下降。
规
规模复制
一次开发 → 全员可用 → 沉淀复用。Skill 数量增长形成飞轮：场景越多 → 数据越多 → Skill 越优。

作业行为审计、权限审批、远程停止、签名校验 —— 给一线开放自动化能力，同时不放弃合规与安全。

OA / Prod 双环境架构 · 工厂的"研发车间"与"量产车间"

two environments, one platform

通过 BUILD_ENV 构建标志分离打包产物：OA 包面向 Skill 开发与测试人员，Prod 包面向一线作业人员。 两者共享内核（Claude Agent SDK + Skill 引擎），但在能力开放程度、来源、可观测性上完全不同。

OA 环境 DEV / TEST

面向 Skill 开发者 · 强能力、弱限制
  • 开发工具集 已有
    apa-builder · skill-creator · DevTools
  • 测试套件 新建
    skill-tester · 录制回放 · Mock 数据
  • 本地热重载 新建
    改文件即时生效，无需重启 session
  • 调试钩子 新建
    PreToolUse / PostToolUse 全量打开
  • Skill 推送 新建
    一键发布到 Registry（待审批）

Skill Registry CENTRAL

企业 Skill 中央仓库 · 治理枢纽
  • 版本管理 规划
    语义版本 · 兼容性矩阵
  • 签名服务 规划
    企业 CA 签发 · 防篡改
  • 审批流 规划
    代码 Review · 安全扫描
  • 灰度策略 规划
    按人群/部门 渐进发布
  • Kill Switch 规划
    远程禁用问题 Skill

Prod 环境 PRODUCTION

面向一线作业人员 · 稳定、可控、可观测
  • 运行时 已有
    Claude Agent SDK + Skill 沙箱
  • 签名校验 必做
    启动时验证 Skill 签名链
  • 权限引擎 增强
    Skill 工具默认拒绝，按需开放
  • 业务遥测 新建
    Skill 调用 / 耗时 / 成功率
  • 异常自愈 新建
    熔断 · 重试 · 降级
  • 远程控制 新建
    停止 / 禁用 / 强升级
流转路径 ： OA 端开发 / 测试 → 推送 Registry（含签名 + 审批） → Prod 端拉取（按灰度策略） → 遥测回流 ↺ 驱动下一轮迭代

06

关键治理机制 · 让生产自动化"敢交付"

make automation trustable

🛡安全与合规

企业自动化的前提是"可控、可审计、可追责"。
  • 工具级审批（canUseTool）— 已有，但 Skill 工具默认放行
  • Skill 签名 / Checksum 校验 — 必须建
  • Skill 安全扫描（敏感数据 / 危险命令）— 已有 skill-vetter 指南，待自动化
  • 操作审计日志（谁在何时做了什么）— 待建
  • macOS 公证 / Windows 正式签名 — 必须办

📊可观测性

没有度量，谈不上"生产化"。
  • 本地日志（electron-log，5MB 轮转）
  • 生命周期 Analytics（GA4 / 百度，3 个事件）
  • 业务遥测（Skill 调用 / 耗时 / 成功率）
  • 错误聚合（Sentry / 自建）
  • 集中监控大盘 + 告警阈值

⚙稳定性与运维

一线作业 7×24，平台必须"扛得住、停得下"。
  • 自动更新（electron-updater 已集成，但未挂载）
  • 远程 Kill Switch（停止 Skill / 禁用 Skill）
  • 异常自愈（熔断 / 重试 / 降级）
  • 灰度发布（按部门 / 人群推 Skill）
  • 多版本兼容（同时支持 N、N-1）

🧪质量与发布

"研发到生产"的中间，要有一道质检闸口。
  • Skill 结构校验（quick_validate.py）
  • Skill Tester（用例 / 录制 / 回放）
  • CI 自动化（PR 触发 Skill 全量回归）
  • Skill Registry 审批流
  • 跨平台兼容矩阵（Mac × Win × 版本）

已就绪 部分就绪 待建设

主要风险与缓解

known risks
级别 风险 影响 缓解动作
高 Skill 无签名校验，恶意 Skill 可能在一线机器执行 合规风险 / 数据泄露 / 业务事故 Phase 1 末实现签名链；启动校验失败拒绝加载；Prod 端默认不接受任何未签名 Skill
高 无远程 Kill Switch，问题 Skill 上线后无法快速止损 故障扩散 · 一线作业被阻塞 Phase 1 实现远程禁用单个 Skill；P95 生效时间 < 30s；同步建告警通道
高 自动更新逻辑未挂载，问题版本无法回滚 用户停留在旧版本，修复无法生效 Phase 1 优先修复；增加版本健康度上报；支持强制升级开关
中 Skill 工具默认放行（Skill 调用不走 canUseTool） 恶意 Skill 可绕过权限审批 用 PreToolUse Hook 重建审批层；高风险工具强制弹窗
中 无业务遥测，无法度量 Skill 价值 难以向管理层证明投入产出 Phase 1 业务遥测打底；Phase 2 建监控大盘 + ROI 仪表盘
中 Skill 升级与 App 升级耦合（随 App 包分发） 每次小修都需要全量升级 Electron 包，体验差 Phase 2 引入独立 Skill 分发通道；增量下载
低 跨平台兼容性差异（Windows 文件 I/O 慢、路径差异） Skill 在 Mac 通过，Win 失败 Skill Tester 强制跨平台回归；CI 双平台并行
低 SDK 升级带来 API 不兼容 需要适配工作量 已有 SDK 隔离层（sdk-config / session-manager）；SDK 升级有缓冲层
